τ0-VLA: a Hierarchical Robot Foundation Model with World-Model-Guided Test-Time Computation

Xiaowei Cai, Jianlan Luo, Buqing Nie, Xiangyu Yue 외 40여 명 (알파벳순) · Agibot Finch · Shanghai Institute of Innovation · CUHK

프로젝트 페이지 PDF arXiv 번호 미부여
Hierarchical VLA World Model Test-Time Computation Beam Search Long-Horizon

High-level Qwen3.5-9B · Low-level Qwen3.5-2B + MoT action expert · 40,115시간 실세계 데이터

한 줄 요약 (TL;DR)

밀크티 만들기처럼 수십 단계가 이어지는 작업에서는, 로봇이 "다음에 뭘 할까"를 매번 한 번의 직감으로 정한다. 문제는 여기서 한 번 잘못 고르면 아무리 손을 정교하게 움직여도 되돌릴 수 없다는 것 — 엉뚱한 일을 완벽하게 해낼 뿐이다. 이 논문은 그 "다음 할 일" 결정에만 생각할 시간을 더 쓰게 만든다. 후보를 여러 개 떠올리고 → 각각을 실행하면 화면이 어떻게 될지 머릿속에서 그려보고 → 어느 쪽이 작업을 더 진척시키는지 채점하고 → 유망한 것만 남겨 몇 수 앞까지 내다본 뒤 결정한다. 사람이 어려운 선택 앞에서만 잠시 멈춰 "이렇게 하면 어떻게 되지?"를 굴려보는 것과 같다. 실제 손발이 되는 하위 모델은 40,115시간 분량 실제 로봇 데이터로 학습했다. 장기 작업 평균 성공률 45%(π0.5 22.5%, GR00T N1.7 2.5%), 학습 때 못 본 배치에서 다음 단계를 맞히는 정확도 74%(한 번에 정하면 50%).

1배경 · 문제의식

방 청소·요리·음료 준비 같은 장기(long-horizon) 조작은 수분~수시간에 걸친 연속적 의사결정을 요구한다. 로봇은 무엇이 끝났고 무엇이 남았는지 추론하고, 중간 결과를 검증하며 국소 실패를 복구해야 한다. 핵심은 "잘못된 subtask 선택은 정밀한 모터 제어로도 되돌릴 수 없다"는 점 — 로봇이 엉뚱한 subtask를 완벽하게 수행할 뿐이다.

대부분의 계층형 VLA는 이 subtask 결정을 매 스텝 단일 forward pass로 내려, 어렵거나 결정적인 선택에 추가 연산을 배분할 메커니즘이 없다. τ0-VLA는 상위 subtask 생성을 연산량으로 확장 가능한 추론(compute-scalable inference) 문제로 재정의한다.

2핵심 Contribution

  • 월드모델 유도 Test-Time Computation — 상위 정책이 필요할 때만 후보 subtask를 탐색. 제안(VLM)→월드모델의 결과 예측→가치모델 채점→beam search→reflect&commit의 파이프라인으로, 추가 연산이 다음-subtask 예측 정확도를 실제로 끌어올림을 실증.
  • 실행 메모리 기반 계층 구조 — 상위 정책이 관찰 정렬 실행 메모리 Mt를 유지하며 언제 추가 연산을 쓸지 스스로 결정. 하위 VLA는 committed subtask를 여러 임바디먼트에서 실행.
  • 대규모 다임바디먼트 파운데이션 — 40,115시간 이질적 실세계 데이터(원격조작·자율수집·UMI)로 멀티모달 공동학습. 장기 이동조작·정밀조작·교차 임바디먼트 일반화를 한 모델로 커버.

3Method

왜 두 층으로 나누나

"밀크티를 만들어"라는 지시를 관절 움직임으로 바로 바꾸기는 어렵다. 그래서 역할을 둘로 쪼갠다 — 상위 정책은 "지금 뭘 할 차례인가"(예: "숟가락을 집어라")를 정하고, 하위 정책은 그 한 문장을 받아 실제 관절 움직임을 만든다. 상위는 무엇을, 하위는 어떻게를 담당한다.

상위 정책이 판단할 때 보는 재료는 네 가지다: ① 전체 목표("밀크티를 만들어"), ② 실행 메모리 — 지금까지 뭘 끝냈는지 적어둔 메모(예: "컵을 놓았음"), ③ 직전에 지시한 일, ④ 현재 카메라 화면. 이걸 종합해 메모를 갱신하고 다음 할 일을 내놓는다.

실행 메모리가 필요한 이유: 카메라 한 장만으로는 "이미 설탕을 넣었는지" 알 수 없는 경우가 많다. 그래서 진행 상황을 글로 적어 들고 다닌다. 이게 있어야 긴 작업에서 같은 단계를 반복하거나 건너뛰지 않는다.

다음 할 일이 직전과 같으면 하던 동작을 계속 이어가고, 바뀌면 새 동작으로 전환한다. 즉 상위 정책은 단계 전환 시점을 스스로 결정하는 역할도 겸한다.

상위 정책 (High-Level Policy)

Qwen3.5-9B VLM. 멀티뷰 관찰 + 태스크 지시 + 실행 메모리 + 직전 subtask를 받아, 추론과 함께 갱신된 메모리 Mt와 직접 제안(direct proposal) zdirt를 산출. 여기서 직접 제안에 곧장 commit하거나, 어려운 결정이면 추가 test-time computation을 호출할 수 있다.

핵심: "생각할 시간을 더 쓰는" 탐색

여기서 test-time computation이란 모델을 더 크게 만들거나 더 학습시키는 게 아니라, 이미 학습된 모델을 실행 시점에 여러 번 돌려 답의 질을 높이는 방식이다. 네 가지 부품이 협업한다.

  • 제안 모델 (P) — "다음에 뭘 할까?"에 대한 후보를 N개 내놓는다. 예: "숟가락 집기", "컵 놓기", "컵 집기".
  • 월드모델 (W) — 각 후보에 대해 "그걸 실행하고 나면 카메라에 뭐가 보일지"를 이미지로 그려낸다. 실제로 해보지 않고 결과를 미리 보는 셈.
  • 가치모델 (V) — 그 상상된 이미지를 보고 "이러면 작업이 얼마나 진척된 건가"를 점수로 매긴다(예: 0.95 / 0.50 / 0.95). 낮은 점수는 잘못된 선택이라는 신호.
  • 반성 모델 (F) — 탐색이 끝나면, 살아남은 후보들과 그 예상 결과를 종합해 최종 하나를 확정한다.

이들을 묶는 것이 beam search다 — 후보를 전부 끝까지 따라가면 경우의 수가 폭발하므로, 매 단계마다 점수 상위 몇 개(B개)만 남기고 나머지는 버리는 탐색법이다. 살아남은 가지를 다시 펼치기를 D번 반복해 몇 수 앞을 내다본다.

비유: 체스에서 모든 수를 다 계산할 순 없으니 유망한 몇 수만 골라 몇 수 앞까지 읽어보는 것과 같다. 다만 여기선 "수를 읽는" 역할을 월드모델이 그린 미래 이미지가 대신한다.

왜 중요한가: 연산을 더 쓸수록 다음 단계 예측 정확도가 실제로 올라가다 포화한다(그림 5). 즉 로봇의 상위 판단력을 재학습 없이 연산만으로 끌어올릴 수 있다는 뜻이며, 쉬운 결정엔 안 쓰고 어려운 결정에만 골라 쓸 수 있다.

하위 정책 — 실제로 몸을 움직이는 부분

상위가 정한 한 문장("숟가락을 집어라")과 함께 여러 각도의 카메라 영상, 로봇 자기 관절의 현재 각도, 그리고 어떤 로봇인지·어떻게 제어하는지를 적은 설명을 받는다. 마지막 항목이 있어야 팔 개수와 구조가 다른 여러 로봇에 같은 모델을 쓸 수 있다.

이걸 조건으로 flow matching(무작위 노이즈에서 정답 궤적 쪽으로 흐르는 방향을 학습해두고, 실행할 때 그 흐름을 따라가 궤적을 완성하는 생성 방식)으로 앞으로 몇 스텝 분량의 움직임을 한 번에 만들어낸다. 매 순간 한 스텝씩 내놓는 대신 묶음으로 내놓으면 동작이 더 매끄럽고 빠르다.

5주요 관찰 · 분석

  • 계층 + 탐색의 결합이 핵심: 단순히 하위 VLA를 잘 만드는 것(직접 실행 27.5%)만으로는 부족하고, 상위 subtask 결정에 월드모델 유도 탐색을 얹을 때(45.0%) 초장기 태스크에서 급격한 이득.
  • 분포 이탈에서 특히 강함: in-domain보다 OOD에서 TTC의 상대 이득이 크다(74% vs Plan Once 50%). 학습 분포 밖 관찰에서 단일 예측이 흔들릴 때 상상·검증 탐색이 보정.
  • 연산-정확도 트레이드오프가 부드러움: 어려운 결정에만 연산을 더 쓰고 쉬운 결정은 직접 제안으로 처리 — 예산을 선택적으로 배분.
