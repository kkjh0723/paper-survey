PhyAgentOS: A Self-Evolving Operating System for Embodied Agents with Decoupled Cognitive Planning and Physical Execution

Yang Liu, Weixing Chen, Xinshuai Song, Tao Pu, Siwen Mo, Yongjie Bai, Zihao Chen, Qianran Sun, Liruo Zhong, Ying Shen, Liang Lin · Sun Yat-sen University 외

arXiv abstract PDF arXiv:2607.16636
Embodied OS Session Runtime State-as-a-File Safety Epistemic Memory

제출: 2026-07-18 · 19+ 시뮬·실체 검증 (Minecraft/StarDojo/DST/LIBERO/Calvin/RoboCasa365)

한 줄 요약 (TL;DR)

Embodied AI 스택은 planner·controller·simulator·real robot이 임시 스크립트로 접합되어 재현성·안전성·재사용성이 취약하다. PhyAgentOS는 이를 운영체제 유사 런타임으로 재정의해 세션(Session)을 최소 스케줄 단위로, Markdown+YAML 파일들의 집합을 상태 표현으로 통일한다(State-as-a-File). SessionVerifier는 "실행 종료 ≠ 의미적 성공"을 판별하고, epistemic memory가 검증된 결과를 지식/교훈으로 축적한다. Minecraft Optimus-67·StarDojo·Don't Starve(DST) 및 LIBERO/Calvin/RoboCasa365 등 19+ 환경에서 계획·검증·안전을 동일 프로토콜로 제공.

1배경 · 문제의식

기존 embodied agent 파이프라인은 (1) planner LLM, (2) VLA/RL controller, (3) simulator/real robot, (4) verification 스크립트가 애드혹으로 연결돼 있어 실패 원인 추적이 어렵고 재사용이 어렵다. 저자들은 이 상태를 "OS 없는 컴퓨팅과 유사"라 진단하고, 세션 스케줄·검증·메모리·안전을 시스템 서비스로 제공하는 embodied OS를 제안한다. 핵심 설계 원칙 두 가지: (a) 인지-실행의 명시적 디커플, (b) 파일 기반 상태 표현으로 사람과 다양한 컴포넌트가 동시에 관찰·수정 가능.

2핵심 Contribution

  • Session-Centered Runtime — 실행 단위를 개별 액션이 아닌 "세션"으로 두고, WatchdogSupervisor가 SESSIONS.md의 대기 세션을 잡아 어댑터 계약 검증→하트비트 모니터링→결과 기록의 bounded lifecycle로 관리.
  • State-as-a-File 프로토콜 — 모든 크로스-프로세스 상태를 사람이 읽는 Markdown+YAML 문서 5종(SESSIONS·SKILLRUNTIME·TARGETS·ENVIRONMENT·LESSONS)로 통일. 스크립트 없이도 사람이 열어 실패 원인 추적·수동 편집 가능.
  • SessionVerifier + Epistemic Memory + Layered Safety — V(G,S₀,ST,τ,H)로 의미적 성공/실패/재계획을 결정, 검증된 결과를 KNOWLEDGE.md/LESSONS.md에 episodic→semantic→methodological로 축적. 5중 안전 레이어(preflight·bridges·SafetyGuard·heartbeat·target-local)로 원리적 fail-safe.

3Method

Session-Centered Runtime

세션은 목표 G, 초기 상태 S₀, 계약 τ(호환성 요구), 예산·타임아웃 H를 담은 요청. WatchdogSupervisor는 SESSIONS.md에서 pending을 pull → Compatibility Preflight(어댑터 IO·능력 검증) → 실행자에게 위임 → Heartbeat로 살아있는지 감시 → 결과·증거를 다시 기록. 실패 시 재시도/취소/재계획을 정책으로 결정.

State-as-a-File (5개 문서)

SESSIONS.md
목표·계약·결과의 트랜잭션 원장 (모든 실행의 진실 소스)
SKILLRUNTIME.md
실행 방법·리소스 요건 (어댑터가 세션을 어떻게 수행하는지)
TARGETS.md
사용 가능한 실체·엔티티와 그 능력 카탈로그
ENVIRONMENT.md
구조화된 환경 스냅샷(관측·객체·좌표계 등)
LESSONS.md
실패 원인·시정 조치의 축적 (자기-진화의 씨앗)

SessionVerifier (의미적 성공 판정)

V(G, S₀, ST, τ, H) → {success, failure, replan}. 컨트롤러 return code 대신 증거-기반 판정(관찰·로그·해시)을 통해 "실행이 끝났다"와 "목표가 실제로 달성됐다"를 분리. 판정 결과가 epistemic memory 갱신을 트리거.

Epistemic Memory (3계층)

Episodic(개별 세션 기록) → Semantic(태스크 레벨 요약) → Methodological(재사용 가능한 절차). 검증된 결과는 KNOWLEDGE.md(성공 패턴), 실패는 LESSONS.md(정정 규칙)으로 통합. 다음 계획 단계에서 planner가 이를 컨텍스트로 활용해 자기-진화.

Layered Safety

다섯 층 방어: (1) Compatibility Preflight(어댑터·리소스 사전 검증) → (2) Action Bridges(결정론적 IO 변환) → (3) SafetyGuard(명령 허용성 실시간 검사) → (4) Heartbeat(오류 감지) → (5) Target-Local Constraints(장치 측 안전 최종 강제).

5Ablation & 통찰

  • SessionVerifier 제거: "완료 신호"만 믿는 컨트롤러에서 조용한 실패(silent failure) 급증 → 상위 계획이 잘못된 전제 위에서 진행됨.
  • State-as-a-File 제거: 실패 재현·인간 개입이 어려워지고 LESSONS 축적이 무너져 자기-진화 소실.
  • Layered Safety의 각 층은 서로 다른 실패 모드를 커버 → 하나라도 빠지면 실체 실험에서 dangerous behavior 발생.
  • OS-스타일 설계는 개별 벤치마크 성능 극대화가 목표라기보다 재현성·안전성·자기-진화 축을 통일하는 데 방점.
